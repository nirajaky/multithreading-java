In Java, a **Thread** is a lightweight unit of execution.
When you run a Java program, JVM itself starts multiple threads internally, and you can also create your own threads.

---

# 1. What is a Thread in Java?

A thread is an independent path of execution inside a process.

Example:

* Chrome browser = Process
* Tabs working independently = Threads

In Java:

* `main()` method runs on the **main thread**
* You can create additional worker threads

Example:

```java
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread is running");
    }

    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.start();
    }
}
```

---

# 2. How Threads are Stored in JVM Memory

A Java application memory is mainly divided into:

```text
JVM Memory
│
├── Heap (shared)
├── Method Area / Metaspace (shared)
├── PC Register (per thread)
├── Java Stack (per thread)
├── Native Method Stack (per thread)
```

Important:

* Some memory is shared among all threads
* Some memory is private to each thread

---

# 3. Thread Memory Structure

```text
                 JVM PROCESS
┌────────────────────────────────────┐
│            HEAP MEMORY             │ ← Shared by all threads
│   Objects, instance variables      │
└────────────────────────────────────┘

       Thread-1             Thread-2
   ┌──────────────┐     ┌──────────────┐
   │ Java Stack   │     │ Java Stack   │
   │ PC Register  │     │ PC Register  │
   │ Native Stack │     │ Native Stack │
   └──────────────┘     └──────────────┘
```

---

# 4. Heap Memory (Shared)

Heap stores:

* Objects
* Instance variables
* Arrays

All threads can access heap objects.

Example:

```java
class Test {
    int count = 0;
}

public class Demo {
    public static void main(String[] args) {

        Test t = new Test();

        Runnable r = () -> {
            t.count++;
            System.out.println(t.count);
        };

        new Thread(r).start();
        new Thread(r).start();
    }
}
```

Here:

* `t` object is in HEAP
* Both threads access same object

That is why synchronization issues happen.

---

# 5. Java Stack (Per Thread)

Each thread gets its own stack memory.

Stack stores:

* Method calls
* Local variables
* Partial results

Example:

```java
void test() {
    int x = 10;
}
```

`x` is stored in thread's stack.

If 5 threads call same method:

* 5 separate copies of `x` exist

---

# 6. Stack Frame

Every method call creates a stack frame.

Example:

```java
void a() {
    int x = 10;
    b();
}

void b() {
    int y = 20;
}
```

Stack:

```text
| b() frame | ← top
| a() frame |
```

When `b()` finishes:

* Its frame is removed

---

# 7. PC Register (Program Counter)

Each thread has its own PC register.

It stores:

* Current executing instruction address

Because:

* CPU switches between threads rapidly
* JVM must remember where each thread stopped

---

# 8. Native Method Stack

Used when Java calls native code:

* C
* C++
* OS-level methods

Example:

* File operations
* Socket operations
* JNI calls

Each thread has separate native stack.

---

# 9. What Happens Internally When Thread Starts

When:

```java
Thread t = new Thread();
t.start();
```

JVM does:

1. Creates Thread object in HEAP
2. Creates native OS thread
3. Allocates:

   * Java Stack
   * PC Register
   * Native Stack
4. Marks thread as RUNNABLE
5. OS scheduler gives CPU time
6. `run()` method executes

---

# 10. Thread Lifecycle

```text
NEW
 ↓
RUNNABLE
 ↓
RUNNING
 ↓
BLOCKED / WAITING / TIMED_WAITING
 ↓
TERMINATED
```

---

# 11. Difference Between start() and run()

## run()

```java
t.run();
```

Normal method call.
No new thread created.

Runs on main thread.

---

## start()

```java
t.start();
```

Creates new thread internally.
Then JVM calls `run()` automatically.

# Tricky Interview Questions

---

## Q1. Are threads stored in heap?

Thread object → Heap
Thread stack → Separate memory outside heap

---

## Q2. Is stack shared between threads?

No.

Each thread has its own stack.

---

## Q3. Are objects inside stack?

No.

Objects are in heap.

Only references may exist in stack.

---

## Q4. Why are local variables thread-safe?

Because each thread has separate stack frame.

---

## Q5. Can two threads execute same method simultaneously?

Yes.

Each gets separate stack frame.

---

## Q6. Why is String immutable useful in multithreading?

Because immutable objects are naturally thread-safe.

---

## Q7. Does synchronized make code faster?

No.
It adds locking overhead but ensures safety.

---

## Q8. Can thread access another thread's stack?

Directly → No

Only its own stack is accessible.

---

## Q9. Where are static variables stored?

In Method Area / Metaspace.

Shared across threads.

---

## Q10. Which memory causes race condition?

Shared memory:

* Heap
* Static area

Not stack memory.
